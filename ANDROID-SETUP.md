# Toddler Coloring Book — Android setup

This kit adds a native Android wrapper while preserving the existing website.
Keep these existing files in the repository root:
`index.html`, `manifest.webmanifest`, `sw.js`, `icon-192.png`,
`icon-512.png`, and `apple-touch-icon.png`.

## App identity
- Android application ID: `com.joellesba.toddlercoloringbook`
- App name: Toddler Coloring Book
- Do not change the application ID after publishing.

## Requirements
Use a Windows or Mac computer with:
- Node.js 22 or newer
- Android Studio
- Android SDK platform and Build Tools required by the current Play target

## First-time setup
Open a terminal in the repository folder and run:

```bash
npm install
npm run android:init
```

This copies the existing web app into the generated `www/` folder and creates
the native `android/` project.

Then open Android Studio:

```bash
npm run android:open
```

Allow Gradle sync to finish. Install any SDK components Android Studio requests.
Run on an Android device or emulator. Test drawing, colors, brush sizes, eraser,
picture selection, clear, and offline launch.

## After changing the website
Run:

```bash
npm run android:sync
```

## Create a Play Store bundle
In Android Studio select **Build > Generate Signed Bundle / APK**.
Choose **Android App Bundle**. Create an upload keystore and store it safely
outside this repository. Keep the keystore and passwords private and backed up.
Never commit the keystore or signing passwords to GitHub.

Use the signed release `.aab` produced by Android Studio for Play Console testing.

## Before release
Complete Play Console's app-content, target-audience, content-rating, Data safety,
privacy-policy, and store-listing sections accurately. Because this is a
child-focused app, review Google Play Families requirements.

Your newer personal developer account will also need the applicable closed test:
12 opted-in testers for 14 continuous days before applying for production access.

## Safety notes
- Do not upload signing keys or passwords to GitHub.
- Keep the Android work on a separate branch until reviewed.
- The original website files should remain in the repository root.
- `www/` is generated by the preparation script; do not edit it directly.
